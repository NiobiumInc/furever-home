🔒 Checker — the “server” (no secret key)

← back · Scores an applicant on encrypted answers. It never receives a secret key, and the scoring runs right here in this browser — not on a server.

1. Receive the applicant’s bundle

⏳ Waiting for an applicant’s encrypted bundle… (it loads automatically when you open this from their QR code).

🔒 Don’t want to use the relay? Use a file instead (nothing touches a server)

Ask the applicant for the bundle file and upload it here — then no relay, and no server, is in the loop at all.

2. Score it (blind)

Two separate steps, on purpose: first compute on the ciphertext (here, in this browser), then send the encrypted result back. The compute is local; only the send touches the network.

🔌 Don’t believe the computing happens here, not on a server? Once the bundle has loaded, turn off Wi-Fi and hit Score — it still computes. Reconnect, then press Send (no need to re-score).

What just happened here?

1. This page received an encrypted bundle — ciphertext + public/eval keys, and no secret key. So it literally cannot read the answers.

2. The scoring ran in this browser, on this device (WebAssembly), directly on the ciphertext. Nothing was sent anywhere to compute it.

3. The result is also encrypted — only the applicant’s secret key, which never left their device, can open it.

4. The relay (if used) was only a pipe moving the encrypted bundle and result between devices — it holds no key and ran no computation.
